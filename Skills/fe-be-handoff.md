# FE-BE Handoff（前后端交接技能）

## 技能用途
- 服务角色：**FE (Frontend Expert) / BE (Backend Engineer)**
- 触发时机：PRD 终稿确认后、契约冻结后，FE/BE 开始各自实现前
- 输出物：前后端交接清单（含数据映射、Mock 方案、自测对照表）
- 适用场景：任何需要前后端协作的功能开发

> 对应 `ai-prd-generator.rules.md` 第 11 节：
> "AI → FE：重点关注 §2 用户场景 + §4 交互需求 + §5 数据需求"
> "AI → BE：重点关注 §3.2 业务规则 + §3.3 状态机 + §3.4 数据模型"
> 本 Skill 将交接过程标准化为可执行的清单与模板。

---

## 0. 核心原则

> 交接的目标是**让 FE 和 BE 各自拿到足够的信息独立开工**。
> 交接完成后，FE 不需要问 BE "这个接口返回什么"，BE 不需要问 FE "这个参数传什么格式"。

**绝对禁止**：
- FE/BE 开工前不执行交接流程
- 交接信息与已冻结的接口契约不一致
- 交接后单方面修改约定而不通知对方

## 1. 交接信息矩阵（Who Needs What）

### 1.1 FE 在交接中需要获取的信息

| 信息类型 | 来源 | 使用目的 |
|---------|------|---------|
| 页面/视图清单 | PRD §4.1 | 确定需要开发几个页面 |
| 交互说明 | PRD §4.2 | 实现用户操作与系统响应 |
| 表单校验规则 | PRD §4.3 | 实现前端校验 |
| 接口契约（请求/响应） | 冻结契约文档 | 构建 API 调用层和 Mock 数据 |
| 状态枚举与文案映射 | PRD §3.3 + 契约 | 渲染状态标签 |
| 验收标准 | PRD §7 | 自测依据 |

### 1.2 BE 在交接中需要获取的信息

| 信息类型 | 来源 | 使用目的 |
|---------|------|---------|
| 业务规则清单 | PRD §3.2 | 实现核心校验逻辑 |
| 状态机定义 | PRD §3.3 | 实现状态流转 |
| 数据模型 | PRD §3.4 | 设计数据库表结构 |
| 接口契约（请求/响应） | 冻结契约文档 | 实现接口逻辑 |
| 非功能需求 | PRD §6 | 性能、安全约束 |
| 验收标准 | PRD §7 | 自测依据 |

| 契约 | Mock 策略 | Mock 数据文件 |

## 5. 状态枚举文案映射

| 状态值 | 文案 | 标签颜色 |
|--------|------|---------|

## 3. BE 交接清单模板

BE 在开始开发前，应产出以下交接清单：

```markdown
# BE 交接清单 - [功能名称]

## 1. 接口开发清单

| 契约编号 | 接口名称 | 方法 | 关联功能点 | 关联业务规则 | 优先级 |
|---------|---------|------|-----------|-------------|--------|
| C-001 | 获取活动列表 | GET | F-001 | R-001 | P0 |
| C-002 | 创建活动 | POST | F-002 | R-002, R-003 | P0 |
| C-003 | 获取活动详情 | GET | F-003 | — | P1 |

## 2. 数据表设计

| 表名 | 关联数据模型 | 核心字段 | 索引 |
|------|-----------|---------|------|
| t_activity | Activity | id, name, start_time, end_time, status | idx_status, idx_time |

## 3. 业务规则实现映射

| 规则编号 | 规则描述 | 实现位置 | 校验时机 |
|---------|---------|---------|---------|
| R-001 | 活动列表按创建时间倒序 | DAO 层 SQL | 查询时 |
| R-002 | 开始时间必须晚于当前时间 | Service 层 | 创建/编辑时 |
| R-003 | 同一场地同一时段不可重复 | Service 层 | 创建/编辑时 |

## 4. 状态流转实现

```text
DRAFT(0) ──创建──→ DRAFT(0)
DRAFT(0) ──发布──→ PUBLISHED(1)   条件：开始时间 > 当前时间
PUBLISHED(1) ──到期──→ ENDED(2)   条件：结束时间 ≤ 当前时间（定时任务）
DRAFT(0) ──删除──→ 物理删除        条件：仅草稿状态可删除
```

## 5. 错误码定义

| 错误码 | 含义 | 触发条件 | 关联契约 |
|--------|------|---------|---------|
| 40001 | 时间冲突 | 同场地同时段存在活动 | C-002 |
| 40002 | 开始时间无效 | 开始时间 ≤ 当前时间 | C-002 |

## 6. 自测对照表

| 验收标准编号 | 测试场景 | 预期结果 | 自测状态 |
|------------|---------|---------|---------|
| AC-001 | 正常创建活动 | 返回成功 + 活动ID | ⏸️ |
| AC-004 | 时间冲突创建 | 返回错误码 40001 | ⏸️ |
| AC-005 | 开始时间无效 | 返回错误码 40002 | ⏸️ |
```

## 5. 与上下游的衔接

### 上游：PM 冻结契约 → FE/BE 交接
- PM 通过 CP-3 检查点冻结契约后，FE 和 BE 基于契约各自产出交接清单
- 交接清单是 FE/BE 独立开发的起点

### 下游：FE/BE 交接 → 并行开发 → 集成
- FE 基于交接清单 + Mock 数据独立开发前端页面
- BE 基于交接清单 + 业务规则独立开发后端接口
- 双方自测通过后，使用集成验证清单进行联调
- 联调通过后，提交 QA 验收
