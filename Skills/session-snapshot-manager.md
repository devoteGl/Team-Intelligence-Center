# Session Snapshot Manager（会话状态快照管理技能）

## 技能用途
- 服务角色：**PM (Tech Lead / PM)**
- 触发时机：工作跨任务、跨工具、跨人接力、长时异步或上下文即将不可用
- 输出物：标准化 SESSION SNAPSHOT
- 适用场景：宿主线程无法可靠承载全部状态，需要保留检查点、冻结契约、待决策项或任务证据的场景

> 对应 `coding-rules.md` 第 9 节：
> "同一 Codex 任务内优先使用宿主线程状态；跨独立任务、跨工具、长时异步或需要审计时才生成快照。"
> "恢复时必须用仓库、项目文档和当前工具状态交叉验证快照，快照不是唯一事实源。"

---

## 0. 核心原则

> SESSION SNAPSHOT 是显式交接载体，不是宿主任务状态、Git、项目文档或证据文件的替代品。
> 快照应压缩当前事实和未决事项，避免复制整段对话或把推测写成事实。

**绝对禁止**：
- 跨任务或审计交接已明确要求快照时省略输出
- 恢复时不核对当前仓库、项目文档或外部状态
- 在快照中遗漏「待决策项」或「冻结契约」信息
- 把快照内容视为高于当前可验证事实

## 1. 快照生成规范（Snapshot Generation）

### 1.1 快照字段定义

生成 SESSION SNAPSHOT 时应包含以下字段；不适用项写“无”：

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| 当前层 | 枚举 | 当前工作所在层 | `implementation` |
| 当前负责人 | 字符串 | 当前 owner 或主 Agent | `主 Agent` |
| 最近决策 | 字符串 | 最近确认的受保护动作或产品决定 | `用户已确认迁移范围` |
| 任务状态 | 列表 | 所有任务的当前状态 | 见模板 |
| 待决策项 | 字符串 | 当前需要人工决策的事项 | `是否将 JWT 迁移至 httpOnly cookie？` |
| 冻结契约 | 字符串 | 当前已冻结的接口契约信息 | `types/auth.ts（已冻结，版本: v1.0）` |

### 1.2 当前层建议值

```text
intake
planning
discovery
implementation
verification
closeout
external-coordination
```

### 1.3 任务状态标记

| 标记 | 含义 | 使用场景 |
|------|------|---------|
| ✅ | 已完成 | 任务已交付并通过验收 |
| 🔄 | 进行中 | 当前正在执行的任务 |
| ⏸️ | 等待中 | 被依赖关系阻塞或等待授权 |
| ❌ | 已驳回 | QA 驳回，需回退修复 |
| 🔁 | 返工中 | 被 QA 驳回后正在修复 |

### 1.4 生成模板

```text
---
📌 SESSION SNAPSHOT（请在新对话开始时粘贴此内容以恢复上下文）
当前层: {planning / discovery / implementation / verification / closeout / external-coordination}
当前负责人: {owner 或主 Agent}
上次检查点: {CP-X} {状态}（{描述}）
任务状态:
  [{标记}] #{编号} {任务描述} → {负责角色} {状态补充}
  [{标记}] #{编号} {任务描述} → {负责角色} {状态补充}
  ...
待决策项: {描述，无则填"无"}
冻结契约: {描述，无则填"无"}
---
```

### 1.5 生成时机

快照按以下条件生成，可落盘到项目声明位置或作为显式交接块输出：

| 时机 | 是否强制 | 说明 |
|------|---------|------|
| 同一 Codex 任务内连续工作 | 默认不生成 | 使用宿主线程、计划与工具状态 |
| 跨独立任务、跨工具或跨设备交接 | 应生成 | 便于接手方恢复 |
| 长时异步、上下文即将不可用 | 应生成 | 防止关键状态丢失 |
| 用户明确要求接力或审计快照 | 必须生成 | 满足显式交付要求 |
| 仅存在普通任务状态变化 | 默认不生成 | 避免每轮重复噪声 |
| 没有跨上下文恢复需求 | 不生成 | 保持轻量 |

## 2. 快照恢复规范（Snapshot Restoration）

### 2.1 恢复入口

当新任务收到 SESSION SNAPSHOT 时，主 Agent 执行以下恢复流程：

### 2.2 恢复检查清单（按顺序执行）

```text
Step 1 → 解析快照中的所有字段
         验证：字段是否完整？是否有缺失？

Step 2 → 逐项确认任务状态
         验证：每个任务的标记是否与描述一致？

Step 3 → 确认当前层与负责人
         验证：owner、文件 ownership 和下一步是否一致？

Step 4 → 确认待决策项
         验证：是否有未决事项需要先处理？

Step 5 → 确认冻结契约
         验证：契约版本是否仍然有效？

Step 6 → 与 Git、项目文档、任务状态或外部系统交叉验证
         有实质冲突或待确认高风险动作时暂停；否则继续范围内工作
```

### 2.3 恢复确认输出模板

```markdown
✅ 上下文已恢复

**恢复摘要**：
- 当前层：{current layer}
- 当前负责人：{owner 或主 Agent}
- 上次检查点：{CP-X} {状态}
- 待处理任务：{N} 个
- 待决策项：{有/无}（{描述}）
- 冻结契约：{有效/无}

**下一步操作**：
- {具体描述接下来要做什么}

如无实质冲突或未决检查点，继续执行下一步；否则列出需要用户裁决的差异。
```

### 2.4 恢复异常处理

| 异常情况 | 处理方式 |
|---------|---------|
| 快照字段缺失 | 先从当前事实补证；影响范围或安全边界时再请求补充 |
| 快照内容与当前代码状态不一致 | 以可验证事实为证据，披露差异；实质冲突时请求裁决 |
| 快照中有未决的 CP 检查点 | 不跳过，重新请求用户确认 |
| 快照版本过旧（跨多个会话） | 建议用户重新评估任务状态 |

## 3. 快照质量自检

PM 在生成快照前，必须执行以下自检：

```markdown
## 快照自检清单

- [ ] 所有快照字段是否都已填写或明确为“无”？
- [ ] 当前层、负责人和文件 ownership 是否匹配？
- [ ] 任务状态列表是否包含了本次会话中提到的所有任务？
- [ ] 已完成的任务是否标记为 ✅？
- [ ] 进行中的任务是否标记为 🔄？
- [ ] 等待中的任务是否说明了等待原因（依赖/授权）？
- [ ] 待决策项是否准确反映了需要人工决策的内容？
- [ ] 冻结契约信息是否包含了版本号？
- [ ] 快照是否放置在响应的最末尾？
```

---

## 4. 与上下游的衔接

### 生成时（满足跨任务或审计触发条件）
- 由主 Agent 汇总，避免多个角色各自产生冲突快照
- 快照必须反映最新的任务、证据和未决状态

### 恢复时（新任务接收快照）
- 由接手任务的主 Agent 负责恢复与交叉验证
- 不因恢复仪式机械阻塞低风险只读检查
- 验证后由主 Agent按当前层、ownership 和风险信号决定下一步
