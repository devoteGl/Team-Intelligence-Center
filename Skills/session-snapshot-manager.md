# Session Snapshot Manager（会话状态快照管理技能）

## 技能用途
- 服务角色：**PM (Tech Lead / PM)**
- 触发时机：每次 AI 响应结束时自动执行（生成快照）；新对话开始时用户粘贴快照后执行（恢复快照）
- 输出物：标准化 SESSION SNAPSHOT
- 适用场景：所有跨对话的任务延续场景

> 对应 `coding-rules.md` 第 7 节：
> "每次响应结束时，AI 必须在末尾输出当前会话状态快照。"
> "新对话恢复协议：用户粘贴快照后，PM 必须先逐项确认快照内容。"

---

## 0. 核心原则

> AI 不具备跨会话记忆。SESSION SNAPSHOT 是唯一的上下文接力机制。
> 快照的准确性直接决定了新对话能否正确恢复工作状态。

**绝对禁止**：
- 省略快照输出（即使当前任务看似简单）
- 在恢复时跳过逐项确认直接开始工作
- 在快照中遗漏「待决策项」或「冻结契约」信息
- 假设快照之外的任何信息仍然有效

---

## 1. 快照生成规范（Snapshot Generation）

### 1.1 强制字段定义

每个 SESSION SNAPSHOT 必须包含以下字段，缺一不可：

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| 当前阶段 | 枚举 | 工作流当前所在阶段 | `[CI] 现状调研` |
| 当前角色 | 枚举 | 当前正在执行的角色 | `CI` |
| 上次检查点 | 字符串 | 最近通过的检查点及描述 | `CP-1 已通过（用户已批准任务清单）` |
| 任务状态 | 列表 | 所有任务的当前状态 | 见模板 |
| 待决策项 | 字符串 | 当前需要人工决策的事项 | `是否将 JWT 迁移至 httpOnly cookie？` |
| 冻结契约 | 字符串 | 当前已冻结的接口契约信息 | `types/auth.ts（已冻结，版本: v1.0）` |

### 1.2 阶段枚举值

```text
[PM] 任务拆解
[CI] 现状调研
[PM] 方案制定
[FE] 前端实现
[BE] 后端实现
[FE/BE] 并行实现
[QA] 测试验收
[DS] 文档归档
```

### 1.3 任务状态标记

| 标记 | 含义 | 使用场景 |
|------|------|---------|
| ✅ | 已完成 | 任务已交付并通过验收 |
| 🔄 | 进行中 | 当前正在执行的任务 |
| ⏸️ | 等待中 | 被依赖关系阻塞或等待检查点 |
| ❌ | 已驳回 | QA 驳回，需回退修复 |
| 🔁 | 返工中 | 被 QA 驳回后正在修复 |

### 1.4 生成模板

```text
---
📌 SESSION SNAPSHOT（请在新对话开始时粘贴此内容以恢复上下文）
当前阶段: [{角色}] {阶段描述}
当前角色: {角色ID}
上次检查点: {CP-X} {状态}（{描述}）
任务状态:
  [{标记}] #{编号} {任务描述} → {负责角色} {状态补充}
  [{标记}] #{编号} {任务描述} → {负责角色} {状态补充}
  ...
待决策项: {描述，无则填"无"}
冻结契约: {描述，无则填"无"}
---
```

### 1.5 生成时机

快照必须在以下时机生成（附加在响应末尾）：

| 时机 | 是否强制 | 说明 |
|------|---------|------|
| 每次 AI 响应结束 | ✅ 强制 | 无论任务是否完成 |
| 检查点通过后 | ✅ 强制 | 更新检查点状态 |
| 角色切换后 | ✅ 强制 | 更新当前角色 |
| 任务状态变更后 | ✅ 强制 | 更新任务标记 |

## 2. 快照恢复规范（Snapshot Restoration）

### 2.1 恢复入口

当用户在新对话开始时粘贴 SESSION SNAPSHOT，PM 必须执行以下恢复流程：

### 2.2 恢复检查清单（按顺序执行）

```text
Step 1 → 解析快照中的所有字段
         验证：字段是否完整？是否有缺失？

Step 2 → 逐项确认任务状态
         验证：每个任务的标记是否与描述一致？

Step 3 → 确认当前阶段与角色
         验证：当前角色是否应该执行下一步操作？

Step 4 → 确认待决策项
         验证：是否有未决事项需要先处理？

Step 5 → 确认冻结契约
         验证：契约版本是否仍然有效？

Step 6 → 输出恢复确认
         格式：见下方模板
```

### 2.3 恢复确认输出模板

```markdown
✅ 上下文已恢复

**恢复摘要**：
- 当前处于 [{阶段}] 阶段
- 当前执行角色：{角色}
- 上次检查点：{CP-X} {状态}
- 待处理任务：{N} 个
- 待决策项：{有/无}（{描述}）
- 冻结契约：{有效/无}

**下一步操作**：
- {具体描述接下来要做什么}

是否继续？（等待用户确认）
```

### 2.4 恢复异常处理

| 异常情况 | 处理方式 |
|---------|---------|
| 快照字段缺失 | 提示用户补充，不自行推测 |
| 快照内容与当前代码状态不一致 | 提示用户确认以哪个为准 |
| 快照中有未决的 CP 检查点 | 不跳过，重新请求用户确认 |
| 快照版本过旧（跨多个会话） | 建议用户重新评估任务状态 |

## 3. 快照质量自检

PM 在生成快照前，必须执行以下自检：

```markdown
## 快照自检清单

- [ ] 所有 6 个强制字段是否都已填写？
- [ ] 当前阶段与当前角色是否匹配？（如阶段是 [CI] 调研，角色应为 CI）
- [ ] 任务状态列表是否包含了本次会话中提到的所有任务？
- [ ] 已完成的任务是否标记为 ✅？
- [ ] 进行中的任务是否标记为 🔄？
- [ ] 等待中的任务是否说明了等待原因（依赖/检查点）？
- [ ] 待决策项是否准确反映了需要人工决策的内容？
- [ ] 冻结契约信息是否包含了版本号？
- [ ] 快照是否放置在响应的最末尾？
```

---

## 4. 与上下游的衔接

### 生成时（响应结束）
- 每个角色在完成工作后，由 PM 统一生成快照
- 快照必须反映最新的任务状态，不可延迟更新

### 恢复时（新对话开始）
- PM 是唯一有权执行恢复操作的角色
- 恢复完成前，任何角色不得开始执行工作
- 恢复后，PM 根据快照中的阶段和角色，决定下一步流转到哪个角色
